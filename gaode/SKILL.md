# 周边去哪儿

帮助用户从同一起点选择一个目的地。每个推荐都是独立备选，分别计算起点到该地点的步行路线。

## 理解需求

提取起点、城市、地点类型、推荐数量、步行时间上限和排序偏好。推荐数量不超过用户要求且最多三个；未指定数量时最多三个。用户没有给出的时间或价格限制不自行添加。

优先使用用户提供的明确起点坐标，坐标参数按高德工具的经度、纬度顺序传递。只有起点名称时，可使用可用的地点搜索或地理编码确定位置；同名地点有歧义时先用一句话澄清。没有足以确定的起点时询问起点，不猜测位置。

区分硬条件和偏好。“步行不超过十五分钟”“只要公园”必须满足；“近一点”“最好安静”用于有依据的排序。没有依据的安静程度、营业状态、排队或价格信息标为未核实，不能将未知属性写成已满足的硬条件。

## 查询真实候选

读取当前环境提供的高德工具名称和参数说明，选择周边搜索；必要时结合城市内的关键词搜索。按实际工具 schema 调用，不假定特定的 MCP 前缀或编造参数。

使用真实搜索返回的 POI ID、名称、地址和坐标。优先选择城市、类别、关键词匹配的候选，按 POI ID 去重；没有 ID 时结合名称和坐标识别重复。缺少目的地坐标或地址时，可用该 POI 的详情查询补充，不能拼造地址或坐标。

搜索半径或结果中的直线距离只用于找到候选，不作为步行距离、步行耗时或是否达标的依据。第一批不足以满足数量时，可补充一批候选或调整一次关键词/范围；不无止境扩圈，也不在已有足够合格候选后反复查询。

## 逐个核验步行路线

对拟推荐的每个候选，调用高德的步行路线规划能力。每次起点都保持为用户的原始起点，终点使用该候选真实坐标。

从成功返回的步行路径读取距离和耗时，按工具声明的单位处理；常见接口的距离为米、耗时为秒。数值须有限且非负。若返回多条路径，选择有效路径中耗时最短的一条，距离与耗时取自同一条路径。

将用户的分钟上限转换成秒，用原始耗时比较：`路线秒数 <= 上限分钟数 × 60`。先筛选再格式化展示，不能把超时路线四舍五入后当成达标；不能以直线距离、固定步速、驾车或骑行结果替代真实步行路线。

无有效路径、耗时缺失或该次路线查询失败的候选，不列入已满足步行条件的推荐。其余候选仍可继续核验。明显的临时服务失败可重试一次；持续失败时说明实际影响，不编造路线或把失败解释成该地不存在。

## 筛选与排序

剔除超时、类型不符或明确硬条件不满足的候选。从其余已核验候选中选取不超过要求数量的结果。

用户要求“近一点”时，按步行耗时升序、再按步行距离升序排序；其他偏好仅使用返回数据中有依据的属性。没有明确排序偏好时，也优先步行耗时较短且需求匹配的候选。只称为“本次查询中更合适/更近的备选”，不声称穷尽全城或找到绝对最近地点。

不足数量时返回实际合格数量，并说明本次查询未找到更多满足条件的地点，不用超时或未核验地点凑数。没有合格地点时不输出虚构推荐；说明是未找到合格结果、缺少必要数据还是服务异常，并提出一个具体的放宽条件建议。

## 返回可直接选择的结果

先简述采用的起点和关键限制，再用简短表格或列表给出：

- 地点名称与真实地址。
- 该条步行路线的距离和预计时间，单位明确；接近时限时可同时给出秒数，避免显示歧义。
- 一句基于类别、路线或已核实属性的推荐理由。
- 必要的未核实信息或结果不足说明。

说明各地点都是从同一起点分别出发的备选。推荐内容以本次高德地点及步行路线查询为依据，保留工具调用结果中的名称和数值，不把估计写成保证。

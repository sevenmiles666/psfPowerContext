## 怎么开始

1. 安装并登录 Qoder，用个人账号，以便最后发布公开站点。
2. 在 Qoder 中打开本地文件夹 `E:\qcoder\psfPowerContext`，无需重新克隆。
3. 新建开发对话，复制下面「开发提示词」的整段内容并发送。也可以直接发送：

   `请阅读 qoder/docs/QODER_START_HERE.md，执行其中的开发提示词。在本次 Qoder 会话中真实完成开发与验证，先不要发布网站。`

4. 从需求拆解开始保留 Qoder 对话记录，尤其是核心代码生成、错误修复和真实检索验证。开发完成后，再用第二段提示词创建 Qoder Sites 网站。

旧原型继续保留；新版本放在 `qoder/papertrail/`，使用独立数据库与应用端口，避免覆盖已经可运行的参考版本。最终提交时明确以新版本为主，并更新入口说明。

## 开发提示词：复制到 Qoder 的开发对话

```text
请在本次 Qoder 开发会话中，实际开发一个可运行的文献与资料检索项目「知页 PaperTrail」，用于 Qoder × OceanBase 比赛。请完成需求拆解、主要代码实现、调试、真实数据库验证、浏览器验证和运行材料；不要只给方案或生成静态界面。

一、真实背景与仓库约束
当前仓库：E:\qcoder\psfPowerContext。
比赛分支：2026-competition-ecosystem，必须保留官方比赛分支祖先。
现有 qoder/ 是 Codex 编写的原型，仅作为需求、界面和接口参考，不属于 Qoder 开发证据。不要把旧实现、旧截图或旧测试结果描述成本次 Qoder 新完成的工作。
请先检查工作区，保留所有已有改动，不执行 reset --hard、clean 或批量删除。
本次在 qoder/papertrail/ 新建独立、完整的正式实现；不要直接复制整个旧目录。参考设计后，在本会话中实现新的前后端、数据模型与测试。
只修改 qoder/，不修改其他赛道目录。不切换到 main，不创建不包含比赛分支祖先的孤立历史。

二、先阅读参考
- qoder/README.md：需求、现有环境与已知限制。
- qoder/docs/design/concept.png：界面视觉参考，不是实际运行证据。
- qoder/docs/screenshots/search-desktop.png、search-mobile.png：旧原型真实界面参考。
- qoder/docs/VALIDATION.md：验收思路。
- 需要时阅读旧 server/ 和 src/，了解原型；记录哪些思路被复用，实际新实现哪些模块。

三、用户与价值
目标用户为需要查找论文、课程笔记、研究资料的学生与科研人员。
核心流程：导入资料 → 按问题或术语检索 → 阅读相关段落及原文上下文 → 核对来源 → 收藏、复制引用、导出阅读清单。
核心目标是找到原文证据，不是生成未经证实的论文结论。

四、本次需要实际实现的主要功能
1. 主题资料库：创建与切换资料库，例如「RAG 文献」「课程笔记」。每份资料、每个片段、收藏与查询记录都要关联资料库。
2. 文献导入：支持含可提取文字的 PDF、UTF-8 Markdown/TXT；显示单文件导入结果；内容摘要去重；有文件体积、页数和文本长度限制。
3. 文本切片：保存文件名、页码、段落与片段编号。长段落合理切分，保留完整源文本用于核对。扫描 PDF 明确提示需要 OCR，不显示虚假成功。
4. 实际 seekdb 存储与索引：真实保存文档、片段、全文索引、语义向量、收藏与操作记录。数据库不可用时返回清晰错误，不能回退成内存模拟检索。
5. 三种检索：关键词、语义、混合。混合模式实际调用 seekdb 的全文与向量检索，并完成可解释的 RRF 排名融合。三种模式都必须严格按资料库过滤，支持进一步限定某份文献。
6. 中英多语言：优先本地 CPU 嵌入模型，无推理 API Key。模型版本固定并缓存，首次下载有清晰提示；更换模型要防止新旧向量混用。不要把字符哈希向量包装成语义理解。
7. 原文核对：点击结果显示源页/源文、段落高亮、完整文件名和页码/段落；引用带逐字原文、来源与稳定片段编号。距离和排序分数不能显示为事实可信度百分比。
8. 阅读清单：收藏/取消收藏、刷新和重启后保留、复制引用、导出 Markdown。没有结果时诚实展示空状态。
9. 文献删除：删除当前资料库内指定文献，清理相关片段与收藏，处理失败重试和一致性；由用户在界面明确确认目标后执行。只允许删除当前资料库所属文献。
10. 可验证记录：记录真实导入与检索，包含资料库、查询、模式、模型版本、返回片段 ID、数据库耗时与总耗时；允许导出 JSON。不要公开真实凭据。

五、界面要求
参照知页设计：白色工作面、浅灰左侧导航、暖橙色点缀、细分隔线，阅读友好，避免密集仪表盘与无意义装饰。
桌面为「左导航 + 中间结果列表 + 右侧原文预览」；手机为顶部导航、纵向结果与原文。
保留品牌「知页 / PaperTrail」和主标题「从资料中，找到答案。」。
主要页面：检索资料、我的文献、阅读清单、使用说明；增加自然易用的资料库切换入口。
所有按钮都实现真实动作；覆盖空资料库、加载、下载模型、导入失败、无匹配、数据库不可用状态。
手机点击“查看原文”应在原文加载完成后滚动到可见位置。
不展示虚构论文、假用户数、假提效百分比、虚假在线体验入口。

六、建议实现与本机环境
可使用 React + Vite 前端、Node.js 后端。依据实际检查选择可靠依赖，并保留锁文件。
本机已有 Node.js 24 和 Docker；旧原型用 8790 端口，请让新应用默认使用 8791。
先检查是否存在运行中的 qoder-papertrail-seekdb 容器，可复用 127.0.0.1:2883 的 seekdb，但新版本使用独立数据库 qoder_papertrail_qoder，不读写旧 qoder_papertrail 数据库。
旧连接默认 root / 空密码只适用于独立本机演示；检查实际配置，不要求在聊天里粘贴凭据。不要停止无关容器、进程或服务。
如需新部署，在新目录提供可复现 Docker Compose；不要与现有 2883 端口冲突。
服务默认仅监听本机。公开站点若只展示项目，不应公开数据库或声称本机应用已在线托管。

七、必须实际执行的验收
使用自编且明确标注的样例，不冒充发表论文。
- 在真实 seekdb 上完成导入、三种检索、文件范围过滤、来源核对和收藏。
- 创建两个资料库，放入可区分的资料；验证三种模式、收藏和文献删除不会跨库泄漏或误操作。
- 重复导入不增加相同片段；无关关键词返回空结果。
- 用至少两页的真实 PDF 验证第 2 页引用；核对长段落的片段定位。
- 导入空白/不支持格式/无文字 PDF 时提示明确，不能产生“成功但零片段”的文献。
- 删除文献后，搜索不再返回它，相关收藏正确清理；重复删除有合理结果。
- 重启应用和数据库后，资料库、文献与收藏仍保留。
- 浏览器走通检索、原文、上传、复制/导出、资料库切换与收藏，检查桌面和手机布局、控制台和 HTML 转义。
修复失败后再报告通过。不复用旧版本证据冒充新版本验证。
```

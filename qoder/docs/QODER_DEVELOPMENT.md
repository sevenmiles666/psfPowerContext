## 实际调试与修复

开发中并非一次通过，主要问题与处理如下：

1. **初始查找说明文件位置不对**：先检查了空的主工作区，随后改用用户提供的附件仓库路径，没有改动其他赛道目录。
2. **长段落单测夹具不足**：原文只能形成四个片段，扩充真实夹具后验证多切片，而不是放宽产品逻辑。
3. **Docker Desktop 未运行导致连接拒绝**：启动本机 Docker Desktop 后，只启动/重启比赛专用 `qoder-papertrail-seekdb`，未停止无关容器。
4. **Transformers.js 新版与既有固定模型缓存不兼容**：试用版本触发远程读取失败后，回到实际可用的 3.8.1，并保留固定模型/revision；另固定依赖补丁版本。
5. **SQL 列数与值数量不一致**：将文献 `status` 从 SQL 字面量改为绑定参数，真实导入随后成功。
6. **PDF.js 6 清理接口变化**：`pdf.destroy()` 不存在，改为对 loading task 调用 `destroy()`。
7. **旧 Node 子进程仍占用 8791**：停止 npm 包装进程后发现旧子进程仍在，确认监听进程属于本项目后只停止该进程，改用直接 Node 后台任务跟踪，避免把旧代码行为当作新修复结果。
8. **PDF 长段落定位断言失败**：字符偏移本身正确，实际原因是 PDF 文本行被重复换行拆成多个段落；调整按 Y 坐标与 EOL 的行组合逻辑。
9. **Markdown 长段落样例不够长**：将自编样例最后一段扩为真实多片段内容，再验证同段不同片段定位。
10. **删除审计查错资料库**：删除发生在第二库，测试最初检查第一库；改为分别检查第一库导入/检索/异常和第二库删除记录。
11. **Windows 浏览器输出路径**：截图与下载路径改用 `fileURLToPath`，避免把 URL 路径直接当 Windows 文件路径。
12. **浏览器脚本语法与滚动证据**：修正 `inputValue()` 拼写；首次手机截图在平滑滚动途中拍摄，随后收紧等待条件并重跑，确保截图展示真实高亮原文。
13. **中文 multipart 文件名乱码**：最新证据检查发现旧断言只验证导入成功，未验证文件名；为 Multer 设置 `defParamCharset: 'utf8'`，新增中文文件名精确断言，并将浏览器上传也改为中文名。
14. **改为中文名后的删除断言遗漏**：一次浏览器运行在删除确认处失败，因为测试仍查找英文旧文件名；修正断言，只清理该次中断留下的明确测试文献，再完整重跑。

依赖安装曾报告无漏洞，但一次独立 `npm audit` 因审计端点错误未完成，所以没有把该次端点失败写成成功安全审计。
